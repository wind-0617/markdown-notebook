## 1. idea-note 精要

### 1.1 代码执行（我们的 FR-03/10 直接对标）
- 每块 = 一个短命子进程：脚本写入私有临时目录，以**文件参数**交给解释器（绝不 `sh -c`，
  防笔记内容被二次解释）；`Stdio::null()` 封 stdin；看门狗杀超时；
- **共享字节预算**：输出超限后只排空不发送（防子进程卡死在满管道）；
- Windows 控制台 GBK 输出用 chardetng 首块嗅探解码；`.bat` 自动 CRLF + `@chcp 65001`；
- 语言表在前端（python `-u`/node/bash/powershell/ruby…+ 自定义执行器），保留字
  （output/input/secret/mermaid）**硬排除运行按钮**；
- 交互式代码提供「在终端运行」逃生舱（写临时文件→拼命令粘贴进 PTY）。

### 1.2 FR-07/08 参数块（独立 ```input 围栏 + 属性绑定 DSL）
```
principal: number = 500000 {slider: 0..2000000, step: 10000, label: 贷款总额}
years:     select = [20, 25, 30] {default: 30}
```
- 行级容错（坏行跳过）；值经**三通道**注入：env 逐字段 / `IDEA_NOTE_INPUT` JSON（32KiB 截断协议）/
  文件字段的 `<name>_path`；
- watch 重跑 = 300ms 防抖；**run=open 四重限险**：每文档每会话只跑一次、只读禁跑、
  会话内首次仍需确认——"git 同步来的笔记在读者点头前执行不了任何东西"。

### 1.3 FR-09 双层设计（最核心的架构启发）
- **默认结果不落盘**：widget 读内存 store，键 = 文件+代码哈希；参数值也只活在内存；
- **显式保存**才写回代码块紧邻的 ` ```output ` 围栏——纯位置约定，零隐藏元数据；
  代码改过 → 按内容定位失败 → **拒绝写回**（"that result no longer describes anything"）；
- 结果协议：stdout **最后一个非空行 = 单行 JSON**，或 `{"idea_note_result":{type,data}}` 信封；
  7 类型（text/markdown/json/table/mermaid/html/image）逐类型严格校验。

### 1.4 FR-11 AI（工具调用循环）
统一 ChatMsg/ToolDef 内部模型 + OpenAI/Anthropic 双适配器；`MAX_ROUNDS=20` 防失控；
手写 15 行 SSE 生成器；8 工具带**三档审批**（ask 默认/ask_all/auto），编辑类先出 diff 预览卡片、
批准仅进 undo 区不自动保存、删除永远要确认；亮点 `component_guide` 工具 = 按需下发规范 +
拼接本机 runner 开关状态（防止模型给禁用的语言写代码）；`mock-ai/server.mjs` 零依赖固定
应答服务让无 Key 也能端到端测试。API Key 明文存 json（其自认缺陷）→ **我们 localStorage 方案反而更好**。

### 1.5 FR-12 Git（纯 CLI，编排在前端）
Rust 侧只找二进制跑命令（多路径探测免 PATH）；**冲突保留双方标记 + 自动完成 merge commit**，
"同步永不阻塞、永不丢数据"；无 remote 时降级为周期性本地快照提交；每仓库读写锁防 index.lock
竞争；凭据一次性 helper → 成功后 approve 升级进系统 helper；`-c` 值白名单校验。

### 1.6 FR-14 加密（换口令不碰笔记文件）
`口令 —Argon2id(salt)→ KEK —unwrap→ MK → 各 ```secret 块`；LUKS 式多 slot（口令+恢复码
同一 try_slot）；**Poly1305 tag 即口令验证器，不存口令 hash**；AAD=块头 `v|key|id`，密文搬家即
ERR_TAMPERED；**明文永不进主文档缓冲/undo/git**（密文常驻，解锁套嵌编辑，保存才批量重加密）；
内容没变的块绝不重加密（新 nonce 会污染 git diff）；锁 TTL 由后端 watchdog 线程强制，不信前端计时器。

## 2. mrmd 精要（FR-09 格式基准）

### 2.1 内联格式（真实测试钉死的行为）
````markdown
```bash
echo hello
```

```output:exec-1771…-ab12c
hello
```
````
- 标准反引号围栏 + info-string 带 execId（`exec-${Date.now()}-${rand5}`），CommonMark 未知
  语言名 → GitHub/VS Code/Pandoc 均原样显示，兼容性最好；
- 重执行 = 按 execId 全局查找**整块替换**；空结果删块（"keep the document clean"）；
  错误写 `[Error: …]` 进同一块；块前后各保一空行；
- 另有 ` ```stdin:<execId> ` 把交互输入历史也持久化；
- **图片不进 output 块**：块正后方插普通 `![plot-1](../_assets/generated/x.png)`，
  重跑先正则删旧图片行；`_assets/` 用 sha256 内容寻址去重 + 孤儿引用检测。

### 2.2 状态纪律（我们该抄的边界）
- 编辑执行状态机（requested→claimed→ready→running→completed）只活在 Y.Map/内存，
  **永不进 .md**；改码不重跑则旧结果原样留着——全仓库精读未见 stale 过期标记，
  这是他们的权衡（纯文本哲学 > 一致性提示），我们的"输出区 data-hash 恢复"已是更好的折中；
- 瞬时状态行 `[status:running] [2/3]` 完成后正则清除；ANSI 转义会入文件（他们接受的代价，**我们不要**）。
- ⚠️ 已知炸点：输出块内打印 ``` 会破坏闭合假设（execId 用 `>`, `_`, `-` 字符集不会撞）。

### 2.3 执行模型与我们的差异
mrmd 是"一个文档一个持久内核"（块间共享变量是其核心卖点）；我们刻意做了相反的选择
（UI 明示"块间独立、无共享内核"）——这规避了 kernel 生命周期、断连存活、跨块依赖全家桶。
未来若做持久内核，参考其"monitor 无头认领执行请求"架构，让执行活在浏览器之外。

## 3. flask-jupyter 精要（常驻内核参照 + 安全反面）

**定性**：master 全仓仅 2 次提交的教学 demo（MIT，668 行单文件 app.py）。本节为**二轮全库源码
精读**结论（`路径:行号` 均来自实际抓取文件），替换首轮误记——它没有"textarea/进程内 exec()"，
而是**真 Jupyter 内核 + Monaco**。

### 3.1 执行模型：常驻内核 + 会话亲和（我们最大缺口的解法样本）
- `KernelManager(kernel_name='python3').start_kernel()` 起独立 IPython 内核进程，
  用 Flask 签名 cookie `session['kernel_id']` + 进程内 `kernels` dict 做句柄亲和（app.py:56-83），
  跨 cell 变量共享由此"天然"成立；
- **三个必改的实现错误**（移植前先修）：
  ① 完成判定 = `get_iopub_msg(timeout=1)` 静默 1 秒即返回，**从不等 shell 通道 execute_reply**
  （app.py:476-516）→ 慢代码返回空 output、结果串到下一块；
  ② 无整体超时/无 `kc.interrupt()` → `while True: pass` 永久卡死该会话；`!pip install` 的
  `communicate()` 也无 timeout；
  ③ `start_kernel()` 不传 cwd → 内核继承 Flask 进程目录，与文件管理器 `codes/` 两套坐标；
- 生命周期泄漏：kernels 无上限无回收，每新 cookie 起一进程；进程重启留孤儿内核；
  **多 worker/Serverless（其 vercel.json 意图）下会话内核必然失效**——部署形态与架构自相矛盾。

### 3.2 输出协议：富媒体"只读了别人跑的，自己跑不出来"
- `/execute_cell` 的 `display_data` 分支只取 `text/plain`→`text/html`，**无 `image/png`**：
  matplotlib-inline 的实时产物被直接丢弃；base64 `<img>` 只出现在打开已存 .ipynb 时
  （fileExplorer.js:150-167）；
- `text/html`（DataFrame 表格）被前端塞 `<pre>` → 显示成字面标签；plotly 有半条链路
  （`plots[]` + `renderPlot()`）但无调用点、plotly 还不在 requirements；
- UI 路径 stdout/stderr 混流（stream 一律 append）；异常只回 ename/evalue，traceback 前端不消费；
- 类型识别靠 `output.includes('array(')` 字符串猜——**反面教材**。
- 对我们的启示：富媒体必须做**端到端**（内核 display 消息 → mime-bundle 契约 → 前端按 mime 分派），
  且 `text/html` 要过 DOMPurify 再 innerHTML。

### 3.3 Monaco 集成：加载链路同款，编辑器形态反面
- cdnjs `loader.js` + `require.config(['vs/editor/editor.main'])` AMD 与 ES Module 混用
  （main.js:9-12）——与我们"单例 + CDN loader"同路数；
- 反面：**每个 cell 一个 Monaco 实例**，cell↔editor 靠私有 `editor._domElement` DOM 反查
  （core/notebook.js:71-74）；自适应高度硬编码 500px 上限 + `onDidChangeModelContent` 手改
  layout 与 `automaticLayout:true` 打架；
- HEAD 活动模块 `addCommand/KeyMod/keydown` **0 命中**：README 承诺的 Shift+Enter/Ctrl+S
  全未实现（我们已实现，见 executor.js）；`/save_notebook` 无任何调用点，"自动保存"是过度承诺；
- 已知 bug 两处：前端打 `/create_folder` 而后端路由是 `/create_directory`（必 404，
  fileExplorer.js:206）；活动模块内 `openInEditor` 未定义，点 .py 文件抛 ReferenceError。

### 3.4 安全：全面反面（建议抄进我们的威胁模型清单）
1. `app.secret_key='your-secret-key-here'` 硬编码（app.py:15）→ 会话可伪造；
2. `CORS(app)` 任意源（app.py:16）+ `/execute_cell` 无鉴权 → **任何网站可对
   localhost:5000 发 drive-by POST 打你笔记本 = RCE**；
3. `app.run(debug=True)`（app.py:667）→ Werkzeug 调试器再叠一重 RCE 面；
4. 执行结果 `innerHTML` 未消毒（core/notebook.js:121-128）→ 内核输出注入 `<script>`；
5. 路径沙箱三套重复实现，全部 `normpath + startswith(CODES_DIR)` 无 realpath →
   **兄弟目录前缀绕过**，配合 `/delete_item` 的 `shutil.rmtree` = 任意目录删除——
   比我们的 basename 白名单弱得多；
6. 探针/变量面板在内核 exec 任意代码且无鉴权（app.py:585-641）。

### 3.5 可借鉴的实用件
- `!pip install` 前置拦截（正则白名单包规格 → `sys.executable -m pip install`，app.py:85-110）
  ——思路实用，需补 timeout + 装完提示"重启内核生效"；
- 变量检查器：内核内遍历 `user_ns` 打印 JSON + 前端 3s 轮询/脏检查（variableInspector.js）
  ——若做 kernel 模式，配套 UI 可照此实现（注意它的探针会写脏 user_ns、pandas 硬依赖两个坑）；
- 存储用标准 nbformat v4，`/save_notebook` 把 outputs/execution_count 一并落盘
  （app.py:381-399）——FR-09 的格式参照，但我们用 sidecar 保 .md 纯净更优（§2 mrmd 结论不变）；
- requirements.txt = 103 行 `pip freeze` 全量转储（连带 jupyterlab/notebook 全家桶）——
  教训：**只列直接依赖 + extras 标可选**（我们 requirements.txt 的做法正确）；
- 事实核查（独立实测，非源码结论）：**`python -I` 不含 `-E`**（`PYTHONPATH=/bad` 实测污染）——
  `-I -E -B` 已采纳进 `executors/python_executor.py`。
