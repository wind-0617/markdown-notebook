# 需求分析文档

> 项目：Markdown 可执行笔记工具 ｜ 状态：V1.0（依据《开发文档》整理）

## 1. 项目背景

传统 Markdown 编辑器只能呈现静态文本，无法满足“边写边跑代码”的交互需求；
Jupyter 支持代码执行，但 `.ipynb` 并非标准 Markdown，难以与其他工具互通。

**本项目填补这一空白**：开发一款基于 Markdown 的可执行笔记工具，让用户既享受
Markdown 的简洁写作体验，又能像 Jupyter 一样直接运行代码块，实现“文档即程序”。

## 2. 目标用户

| 用户类型 | 特征描述 | 核心诉求 |
|---------|---------|---------|
| 程序员/开发者 | 写技术文档、教程、API 示例 | 文档中直接运行代码验证效果 |
| 数据科学家 | Python 数据分析，记录分析过程 | 交互式调参，实时查看结果 |
| 技术写作者 | 技术博客、教程、学习笔记 | 读者可直接改参数、运行代码 |
| 教育工作者 | 编程教学课件 | 学生动手实践，降低学习门槛 |
| 终身学习者 | 自学编程 | 边学边练，笔记即实验环境 |

## 3. 用户痛点

1. **工具割裂**：写作与跑代码来回切换，效率低。
2. **静态文档**：读者无法运行和验证代码。
3. **结果丢失**：执行结果无法保存，重开需重跑。
4. **缺乏交互**：无法嵌入滑块、下拉菜单等控件调参。
5. **协作困难**：笔记散落本地，难以版本管理与同步。

## 4. 功能需求

### 阶段一：MVP 核心功能

| 编号 | 功能 | 描述 | 优先级 | 实现落点 |
|------|------|------|--------|---------|
| FR-01 | Markdown 编辑 | Monaco Editor 编辑体验 | P0 | `frontend/js/editor.js` |
| FR-02 | 实时预览 | 编辑内容实时渲染 HTML | P0 | `frontend/js/preview.js` |
| FR-03 | 代码执行 | 一键运行 Python 代码块并显示输出 | P0 | `/api/execute` + `executors/` |
| FR-04 | 语法高亮 | Markdown 与代码块高亮 | P1 | Monaco + highlight.js |
| FR-05 | 文件管理 | 新建/打开/保存 `.md` 笔记 | P1 | `/api/notes` + `note_service.py` |
| FR-06 | 快捷键 | `Shift+Enter` 执行、`Ctrl+S` 保存 | P1 | `frontend/js/app.js` |

### 阶段二：交互增强功能

| 编号 | 功能 | 描述 | 优先级 | 实现落点 |
|------|------|------|--------|---------|

| FR-08 | 参数联动执行 | 调整控件自动重跑并更新结果 | P1 | `controls.js` → `/api/execute` |

## 5. 非功能需求

| 编号 | 需求 | 描述 | 框架对应 |
|------|------|------|---------|
| NFR-01 | 安全性 | 代码执行沙箱化 | `EXECUTOR_MODE=docker` + 超时/限额 |
| NFR-02 | 性能 | 输入延迟 <100ms；执行超时可配置（默认 30s） | 预览防抖 + `EXEC_TIMEOUT` |
| NFR-03 | 可扩展性 | 模块化，易加新语言/插件 | 执行器注册表 `executors/base.py` |
| NFR-04 | 跨平台 | Windows / macOS / Linux | 纯 Python + 浏览器 |
| NFR-05 | 数据可移植 | 标准 `.md` 存储 | `notebooks/*.md` 纯文本 |
| NFR-06 | 易用性 | 界面简洁，开箱即用 | 单命令启动 |
