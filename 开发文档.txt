# Markdown 可执行笔记工具 —— 项目文档


## 第一部分：需求分析

### 1.1 项目背景

在技术学习和知识管理领域，Markdown 已成为最流行的写作语言。然而，传统的 Markdown 编辑器只能呈现静态文本，无法满足技术写作中“边写边跑代码”的交互需求。与此同时，Jupyter Notebook 虽然支持代码执行，但其 `.ipynb` 格式并非标准 Markdown，难以与其他工具互通。

**本项目旨在填补这一空白**：开发一款基于 Markdown 的可执行笔记工具，让用户既能享受 Markdown 的简洁写作体验，又能像 Jupyter 一样直接运行代码块，实现“文档即程序”的交互式编程笔记。

### 1.2 目标用户

| 用户类型 | 特征描述 | 核心诉求 |
|---------|---------|---------|
| **程序员/开发者** | 日常写技术文档、教程、API 示例 | 在文档中直接运行代码验证效果 |
| **数据科学家** | 用 Python 做数据分析，需要记录分析过程 | 交互式调整参数，实时查看结果 |
| **技术写作者** | 撰写技术博客、教程、学习笔记 | 让读者能直接修改参数、运行代码 |
| **教育工作者** | 编程教学，需要可交互的课件 | 学生能动手实践，降低学习门槛 |
| **终身学习者** | 自学编程和技术 | 边学边练，笔记即实验环境 |

### 1.3 用户痛点

1. **工具割裂**：写作用 Markdown 编辑器，跑代码用 Jupyter/IDE，来回切换效率低。
2. **静态文档**：传统 Markdown 只能展示代码，读者无法运行和验证。
3. **结果丢失**：代码执行结果无法保存，下次打开需要重新运行。
4. **缺乏交互**：无法在文档中嵌入滑块、下拉菜单等交互控件来动态调整参数。
5. **协作困难**：笔记散落在本地，难以版本管理和远程同步。

### 1.4 功能需求

#### MVP 核心功能（阶段一）

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| FR-01 | Markdown 编辑 | 基于 Monaco Editor 的 Markdown 编辑体验 | P0 |
| FR-02 | 实时预览 | 编辑区内容实时渲染为 HTML 预览 | P0 |
| FR-03 | 代码执行 | 一键运行 Python 代码块，显示输出结果 | P0 |
| FR-04 | 语法高亮 | Markdown 和代码块的语法高亮显示 | P1 |
| FR-05 | 文件管理 | 新建、打开、保存 `.md` 笔记文件 | P1 |
| FR-06 | 快捷键支持 | `Shift+Enter` 执行代码，`Ctrl+S` 保存等 | P1 |

#### 交互增强功能（阶段二）

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| FR-07 | 交互式参数块 | 在代码块中定义滑块、下拉菜单等控件 | P1 |
| FR-08 | 参数联动执行 | 调整控件参数自动重新执行代码并更新结果 | P1 |
| FR-09 | 结果内联保存 | 执行结果保存到 Markdown 文件中，下次自动恢复 | P2 |
| FR-10 | 多语言支持 | 支持 Python、JavaScript、Shell 等语言的代码执行 | P2 |

#### 智能增强功能（阶段三）

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| FR-11 | AI 笔记助手 | 基于 LLM 的问答、总结、润色、代码生成 | P2 |
| FR-12 | Git 远程同步 | 本地 Git 版本管理 + 远程仓库同步 | P2 |
| FR-13 | 文件树管理 | 完整的项目文件树，支持文件夹浏览和拖拽整理 | P3 |
| FR-14 | 内容加密 | 支持笔记内容加密保护 | P3 |

### 1.5 非功能需求

| 编号 | 需求 | 描述 |
|------|------|------|
| NFR-01 | **安全性** | 代码执行必须在沙箱环境中运行，防止恶意代码危害系统 |
| NFR-02 | **性能** | 编辑器输入响应延迟 < 100ms，代码执行超时时间可配置（默认 30 秒） |
| NFR-03 | **可扩展性** | 模块化设计，方便后续增加新语言支持和功能插件 |
| NFR-04 | **跨平台** | 基于 Web 技术，支持 Windows、macOS、Linux |
| NFR-05 | **数据可移植** | 笔记以标准 `.md` 格式存储，用户可随时迁移到其他工具 |
| NFR-06 | **易用性** | 界面简洁，学习成本低，开箱即用 |


## 第二部分：项目规划

### 2.1 开发里程碑

| 阶段 | 周期 | 里程碑 | 交付物 |
|------|------|--------|--------|
| **阶段一：MVP** | 第 1-3 周 | 可用 Web 编辑器，支持 Markdown 编辑和 Python 执行 | 可运行 Demo |
| **阶段二：交互增强** | 第 4-6 周 | 交互式参数组件 + 结果持久化 | 功能增强版本 |
| **阶段三：智能增强** | 第 7-9 周 | AI 助手 + Git 同步 | 完整版本 |
| **测试与部署** | 第 10 周 | 功能测试、安全审计、部署上线 | 正式发布 |

### 2.2 技术选型

| 层级 | 技术 | 选型理由 |
|------|------|----------|
| **后端框架** | Flask | 轻量、灵活，适合快速开发，Python 生态完善 |
| **前端编辑器** | Monaco Editor | VS Code 同款编辑器，功能强大，体验优秀 |
| **前端框架** | 原生 HTML/CSS/JS | 降低复杂度，便于新手理解和修改 |
| **UI 样式** | Tailwind CSS | 快速构建美观界面 |
| **代码执行** | subprocess + Docker | 本地开发用 subprocess，生产环境用 Docker 沙箱 |
| **AI 集成** | OpenAI 兼容 API | 支持多种 LLM（DeepSeek、GPT 等），灵活可替换 |
| **版本控制** | GitPython / 命令行 Git | 成熟的 Git 操作方案 |
| **数据存储** | 本地文件系统 (.md) | 标准格式，可移植性强 |

│   │   ├── git_service.py           # Git 同步服务

│       ├── preview.js               # 预览渲染
│       ├── executor.js              # 代码执行

│       └── ai-panel.js              # AI 助手面板

### 2.4 风险评估

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| **代码执行安全漏洞** | 高 | 中 | 使用 Docker 沙箱隔离，限制系统资源，设置超时 |
| **AI API 调用成本** | 中 | 中 | 支持本地模型（Ollama），用户自备 API Key |
| **Monaco Editor 学习曲线** | 低 | 中 | 参考 flask-jupyter 已有实现 |
| **多语言执行兼容性** | 中 | 低 | 分阶段支持，优先 Python，逐步扩展 |
| **项目范围蔓延** | 高 | 高 | 严格按三阶段推进，每个阶段有明确交付物 |

### 2.5 资源估算

| 资源 | 估算 |
|------|------|
| **开发人力** | 1 人（全职），约 10 周 |
| **服务器** | 开发阶段本地即可，生产环境需 1 台云服务器 |
| **第三方服务** | AI API（可选）、Git 托管平台（可选） |
| **预算** | 主要是时间和云服务器费用，无额外软件采购成本 |

### 3.2 文档规范

- **格式**：统一使用 Markdown 格式，便于版本管理和协作
- **版本**：所有文档跟随代码仓库进行版本管理
- **更新**：功能变更时同步更新对应文档
- **评审**：重要文档（需求、API）需经过评审
